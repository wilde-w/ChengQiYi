# 验收脚本

`pytest` 测的是**数据**（事件对不对、seq 连不连续、工具返回有没有截断）。
这个目录里测的是**用户看得见的东西**：界面长什么样、点下去有没有反应、
刷新之后还在不在。

差别不是形式上的。工具卡被自己的排版压成一行一个字那个 bug，27 个单测和
30 项 HTTP 走查都没抓住——卡片在数据上完全正确，只是几何坏了。**几何只能
在真浏览器里量。**

## 跑之前

| `agent_api_check.py` | ✓ | | ✓（一轮约 10–60s） |

```bash
cd backend && nohup .venv/Scripts/python.exe -m app.server >> server.log 2>&1 &
# 前端
cd frontend && nohup npx vite --host 127.0.0.1 > /d/tmp/vite.log 2>&1 &
```

## 各自在守什么

- **`agent_api_check.py`** —— 故事工坊的接口走查：建会话 / 发消息 / 读 SSE /
  拉快照 / 撞 404、409 / 停止。30 项，含「帧 seq 从 1 连续」和「停止后流以
  终态收尾」。**读 SSE 时不能读到 EOF**：这条流的寿命是会话的，跨回合常驻，
  脚本自己得知道什么时候停。
- **`agent_e2e.py`** —— 端到端验收：顶栏入口、面板能拖动、工具卡 ≥ 2 张、
  **卡片几何没有被挤扁**、带耗时、改稿后第二版与第一版不同、刷新后
  正文 / 卡片 / 对话重建。截图落在 `E2E_OUT`（默认 `D:/tmp`）。
- **`drag_check.py`** —— 面板拖动：位移与鼠标一致、边界（拖不丢）、
  非抓取区拖不动、关掉再打开回到居中。
- **`story_head.py`** —— 抽查最近几次会话的正文开头：模型有没有把
  「我先去查查」这类前言印进正文栏。只读。

## 两个坑（都真踩过）

1. **抓取点要落在视口里。** `drag_check.py` 第一版按「面板中心」取点，
   而面板被拖到边上之后中心已经在屏幕外——鼠标按下去什么也没抓到，
   于是边界检查在什么都没发生的情况下判过。取「面板 ∩ 视口」的中点。
2. **`agent_e2e.py` 里 `wait_turn` 必须先等开始、再等结束。** 只等
   「停止按钮不可见」的话，按下的那一瞬它就不可见（请求还没发出），
   循环立刻退出，读到的是上一版正文——一个只在测试里出现、看起来像
   产品坏了的假象。
